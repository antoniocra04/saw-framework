<p align="center"><strong>Семь раз отмерь, один раз отрежь — для кода, написанного ИИ.</strong></p>

Saw — воркфлоу разработки с гейтами качества для ИИ-агентов. Он живёт внутри вашего
репозитория и превращает «агент сказал, что готово» в «агент доказал, что готово»:
ничего не мёржится, пока спека не проверена, каждый критерий приёмки не подтверждён
реальным выводом команд, а независимый QA-агент не вынес вердикт PASS.

Работает на [opencode](https://opencode.ai). Опциональный kanban-UI —
[Vibe Kanban](https://github.com/BloopAI/vibe-kanban). Подходит для любого языка и
стека: Saw ставит *процесс* разработки, а не фреймворк.

## Зачем

ИИ-агенты ошибаются предсказуемо:

- **Выдумывают требования.** Просишь фикс — получаешь рефакторинг трёх посторонних файлов.
- **Сами себе ставят оценки.** «Все тесты проходят» — а никто ничего не запускал.
- **Дрейфуют.** Особенно дешёвые модели: каждый шаг чуть-чуть мимо, и это быстро накапливается.
- **Теряют контекст.** Закрыл сессию — потерял план.

Обычный ответ — «возьми модель поумнее и промпт получше». Ответ Saw — **процесс**:
та же дисциплина, которая позволяет человеческим командам стабильно выпускать продукт
силами неидеальных разработчиков — спеки, разделение ролей, независимое ревью,
доказательства — закодирована в файлах репозитория и обеспечена *правами* агентов,
а не вежливыми просьбами в промпте.

Результат: **дешёвые модели дают надёжный результат**, потому что качество
гарантирует процесс, а не модель. Дорогие токены — на спеки и ревью; дешёвые — на
набор кода.

## Как это работает

```
 идея ──/spec──▶ СПЕКА ──/implement──▶ КОД ──/qa──▶ ВЕРДИКТ ──/security-check──▶ ──/pre-pr──▶ PR ──▶ merge
                 проверяемые AC,       атомарные     независимый,     фикс-         evidence     ТОЛЬКО
                 out-of-scope,         коммиты,      на доказа-       чеклист       pack         ЧЕЛОВЕК
                 разбивка на шаги      тест после    тельствах,
                                       каждого шага  может отклонять ∞
```

1. **Гейт спеки.** Нет спеки с проверяемыми критериями — нет кода. Спеку пишет
   агент-аналитик (BSA), принимаете её вы. Агент, обнаруживший недостающие или
   противоречивые требования, обязан остановиться (`BLOCKED`), а не импровизировать.
2. **Разделение ролей — правами, не просьбами.** Шесть агентов с разными правами на
   файлы: исполнитель не может писать QA-отчёты, QA не может трогать код
   (`edit: deny` — жёсткое правило конфигурации).
3. **Независимая проверка.** QA работает в свежем контексте, не видит рассуждений
   исполнителя и обязан вставить реальный вывод команды для каждого критерия.
   Пустое доказательство = FAIL. Отклонять работу может сколько угодно раз.
4. **Состояние на диске.** Спеки, статусы, QA-отчёты, evidence — файлы в
   `.workflow/`. Убивайте сессию когда угодно; `/check-workflow` покажет, где вы
   и что запускать дальше.
5. **Мёржит человек.** Агенты готовят PR с пакетом доказательств; финальный «рез» — ваш.

## Быстрый старт

**Новый проект** (любой стек — первая задача поднимет какой захотите):

```bash
npx create-saw-app my-project
cd my-project
opencode
```

**Существующий проект** (любой язык; ничего не перезаписывает, идемпотентно):

```bash
cd your-project
npx create-saw-app init
```

**Вручную**: скопируйте `AGENTS.md`, `opencode.json`, `.opencode/`, `.workflow/`
в корень репозитория — opencode подхватит всё сам.

Дальше, внутри opencode:

```
/spec Добавить rate limiting в публичное API. Критерии: 429 после N запросов/мин,
      покрыто тестами, существующие эндпоинты не затронуты. Out of scope: изменения авторизации.
```

Прочитайте сгенерированную спеку (ваша единственная важная работа), затем — по шагам:

```
/start-work TASK-001 → /implement TASK-001 → /qa TASK-001 → /security-check TASK-001 → /pre-pr TASK-001
```

…или весь конвейер одной командой:

```
/run-task TASK-001        # все гейты, максимум 3 итерации QA, остановка перед merge
```

Хотите UI — `npm run board` откроет Vibe Kanban; карточка с `/run-task-vk TASK-001`
прогонит гейты в изолированном git worktree. См. [docs/vibe-kanban.md](docs/vibe-kanban.md).

## Возможности

- **Разработка через спеки** — проверяемые критерии приёмки или никакого кода
- **Независимый QA с правом отклонять** — свежий контекст, read-only на код
- **Доказательства, а не заявления** — критерий засчитан только с реальным выводом команды
- **Роли, обеспеченные правами** — границы в конфиге агентов, не в промптах
- **Автономные конвейеры** — `/run-task` (одна задача), `/run-backlog` (пачка с авто-merge и откатом одной командой)
- **Безопасная параллельность** — `depends:` во frontmatter спеки управляет порядком старта
- **Kanban-оркестрация** — опциональная интеграция с Vibe Kanban
- **Не зависит от языка и стека** — процесс едет вместе с репозиторием
- **Самоулучшение** — `/retro` находит повторяющиеся ошибки и патчит сам harness

## Когда Saw *не* нужен

- **Одноразовые прототипы.** Гейты стоят времени; если код выбросят — пропустите процесс.
- **Исследовательские спайки.** Спека предполагает, что вы знаете, что такое «готово».
- **Скрипты до ~50 строк.** Накладные расходы превысят пользу.

Saw силён там, где корректность важнее скорости первого черновика: продукты, API,
всё, на чём будут строить дальше — люди или ИИ.

## Требования

- [git](https://git-scm.com) — воркфлоу живёт на ветках и коммитах
- [opencode](https://opencode.ai) — исполняет агентов и команды
- Node.js ≥ 18 — только для `create-saw-app` и опциональной доски Vibe Kanban
